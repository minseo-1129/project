# 디자인 아카이빙 파이프라인

## 공통 셸과 콘텐츠 수정

전체 프로젝트의 프로토타입과 UX 포트폴리오가 공통 셸을 사용합니다. 글은 각 프로젝트의 `content.md`에서 수정하세요. 화면 선택·플로우 연결은 `project.json`, 공통 디자인은 `shared/`에서 관리합니다.

수정 방법과 파일 역할은 **[CONTENT_GUIDE.md](CONTENT_GUIDE.md)**에 정리했습니다. 프로젝트별 참고 자료는 `<project>/docs/`에 넣고 자료 목록을 작성하면 됩니다. 저장소 루트의 `index.html`에서 전체 프로젝트를 탐색할 수 있습니다.

기존 전체 프로토타입은 각 프로젝트의 `prototype.html`에 보존했습니다. CUPPO는 기존 `CUPPO Prototype.dc.html`을 그대로 사용합니다. 원본 화면 컴포넌트와 에셋은 계속 재사용합니다.

이 프로젝트는 과거 UI/UX 작업물을 코드로 복원·발전시켜 아카이빙한다.
새 작업물이 들어오면 아래 4개 산출물을 이 순서로 만든다.

## 산출물 4종 (파일명 규칙)

| 산출물 | 파일명 | 역할 |
|---|---|---|
| 1. 화면 컴포넌트 | `<Product>Screen.dc.html` | 모든 화면을 `screen` prop 하나로 전환하는 단일 DC |
| 2. 디자인 시스템 보드 | `<Product> Design System.dc.html` | 컬러·타입·간격·컴포넌트 인벤토리 |
| 3. 인터랙티브 프로토타입 | `<Product> Prototype.dc.html` | 좌측 고정 폰 + 우측 화면 갤러리, 클릭 이동 |
| 4. 케이스 스터디 캔버스 | `<Product> Case Study.dc.html` | 1400px 세로 스택 캔버스, 포폴용 |

버전을 올릴 때는 `V2` 접미사로 파일을 새로 만들고 원본은 남긴다 (`WinnusScreenV2.dc.html`).

## 작업 순서 (항상 이 순서)

1. **자료 읽기** — PDF/이미지/발표자료를 먼저 전부 읽는다. 리서치 문서가 있으면
   **그게 리디자인의 근거다.** 인용 가능한 숫자(인터뷰 코딩 카운트, 설문 %)를 뽑아둔다.
2. **원본 진단** — 리서치 데이터와 원본 디자인이 **어긋난 지점**을 찾는다.
   케이스 스터디의 척추는 언제나 "데이터는 A라고 했는데 디자인은 B를 하고 있었다"이다.
3. **디자인 시스템 확정** — 팔레트 8색 이내, 타입 4단계, 컴포넌트 6개 내외를 먼저 정하고 vocalize.
4. **Screen DC** — 화면을 전부 한 파일에. `<sc-if>`로 분기, `screen` prop으로 전환.
5. **Prototype DC** — Screen DC를 두 번 임포트(고정 폰 1 + 썸네일 N).
6. **Case Study DC** — 캔버스 모드, 1400px 고정폭 섹션 세로 스택.

## 고정 규칙

- 화면 크기: 모바일 360×780 (Android). 썸네일은 `transform: scale(0.55)`.
- 썸네일 프레임에 `textAlign: 'left'` 필수 — 부모 button의 정렬이 상속된다.
- 상태바에는 `statusBg`를 명시 (다크 화면에서 흰 글씨가 흰 배경에 묻힘).
- 캔버스 문서는 `<meta name="design_doc_mode" content="canvas">`.
- 프로토타입 좌측 폰은 `position:sticky` + `max-height:calc(100vh - 72px); overflow:auto`.
- 플레이스홀더 이미지는 대각 스트라이프 + 모노스페이스 라벨. SVG 일러스트 금지.
- 한/영 병기는 캔버스에서만. 앱 화면 안에서는 한국어 우선, 영문은 모노스페이스 캡션으로.
- 데이터에 없는 숫자를 지어내지 않는다. 가설이면 "가정"이라고 표기한다.
